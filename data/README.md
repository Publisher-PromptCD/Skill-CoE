# Task lists

`splits/alfworld.json`, `splits/appworld.json`, and `splits/scienceworld.json` are
ready to pass to `skill-coe-train --data`. They contain three arrays:

- `batches`: training batches in learning order; tasks within each batch are unordered.
- `validation`: the fixed tasks evaluated after each update.
- `test`: the fixed tasks used for the final evaluation of the best validation version.

Training is the concatenation of `batches`; there is no separate training list.
All three sets are disjoint. Keep batch order, batch membership, and evaluation
task sets unchanged when comparing methods. Tasks within a batch can be executed
in any order or concurrently, using the same pre-update Skills. Updates occur
after the batch is collected. Array positions record tasks; they do not prescribe
a learning order within the batch.

## Task identifiers

ALFWorld uses a game file path relative to `environment.data_root`:

```json
{"gamefile": "json_2.1.1/train/TYPE/trial_ID/game.tw-pddl", "split": "train"}
```

The `split` value is `train`, `validation`, or `test`. The supplied lists use
60 training tasks, 60 `valid_seen` validation tasks, and all 134 `valid_unseen`
test tasks. Game paths identify specific environment instances.

Download the official ALFWorld data and set `environment.data_root` to the directory
containing `json_2.1.1/`. Each listed task loads the file at
`<data_root>/<gamefile>`. For example, a `gamefile` beginning with
`json_2.1.1/train/` is found under that subdirectory of the downloaded data.
Set `environment.native_config_path` to the official `config_tw.yaml` file.
The adapter selects that exact game; no separate copy of the 60 training tasks
is needed. Keep the original directory layout.

AppWorld uses its native task ID:

```json
{"task_id": "0d8a4ee_1"}
```

The supplied lists contain 45 training tasks, all 57 dev tasks, and all 168
test-normal tasks. The runtime data directory must contain these task IDs.

After installing AppWorld, download its official data with `appworld download data`
in the desired AppWorld root directory. Set `environment.data_root` to that root,
which contains the `data/` directory, rather than to `data/` itself. A listed
`task_id` maps to `<data_root>/data/tasks/<task_id>/`; for example,
`0d8a4ee_1` maps to `<data_root>/data/tasks/0d8a4ee_1/`.
The adapter passes the ID to AppWorld's native task loader, which loads the task
specification and application state. Do not extract only the instruction text or
rename the task directory.

ScienceWorld identifies an instance by task name and variation ID:

```json
{"task_name": "boil", "variation_id": 14}
```

All 30 task types are covered. Training and validation each contain two instances
per type, sampled from the official train and dev splits with seed 42. Test selects
up to ten instances per type from the official test split in ascending variation-ID
order, yielding 271 tasks. Each training batch has 12 distinct task types.

ScienceWorld instances are generated by the installed environment, rather than
selected from a directory of task files. Install ScienceWorld 1.2.3 and Java;
no `environment.data_root` is required. The adapter loads each pair through
`env.load(task_name, variation_id, simplificationStr=..., generateGoldPath=False)`.
For the example above, it loads task `boil`, variation `14`. The same pair selects
the same task instance; the configuration separately controls simplifications.

## Custom lists

Create a JSON object with `batches`, `validation`, and `test`, using the task format
above. Keep all sets disjoint and each batch within the configured
`learning.batch_size`. If initial Skills are built from separate Source tasks,
exclude those tasks from all three sets. Validation and test trajectories must not
be used to generate Skills.

Install the corresponding benchmark version and retain its official split
membership when creating new lists.
